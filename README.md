# GearVault

Маркетплейс для покупки/продажи игровых ценностей: аккаунты, внутриигровая валюта, скины и предметы, услуги прокачки (бустинга), ключи и подписки. Идейный ориентир — площадки вроде FunPay (каталог + продавцы + сделки + чат), но дизайн, тексты и код — самостоятельные.

Полноценное веб-приложение с сервером и базой данных: товары, пользователи, заказы и сообщения сохраняются между заходами, а не живут только в браузере.

## Стек
- Backend: Node.js + Express
- Шаблоны: EJS (серверный рендеринг)
- БД: SQLite (через better-sqlite3), файл создаётся автоматически при первом запуске
- Сессии: своё хранилище на той же SQLite-базе (переживают перезапуск сервера)
- Стили: чистый CSS, без сборщиков

## Дизайн

Тёплая, спокойная эстетика «хранилища»: угольно-тёмный фон, приглушённая латунь/бронза как акцент, шалфейно-зелёный как дополнительный цвет. Заголовки — Fraunces (антиква), текст — Inter. Редкость товара обозначена тональной полосой слева на карточке и мягким свечением при наведении. Возле логотипа и на пустых состояниях — мотив концентрических колец («дверь сейфа»).

## Возможности
- Каталог реальных популярных игр (Фортнайт, CS2, Бравл Старс, Roblox, Steam и ещё полтора десятка) — у каждой игры своя страница с вкладками-категориями (Общее / Аккаунты / Донат / Скины и предметы / Прокачка и бустинг / Ключи и подписки / Подарки / Прочее)
- Поиск игр работает и на русском, и на английском, с сокращениями и опечатками ("бр" находит "Бравл Старс", "cs"/"кс" — CS2) — автодополнение в шапке сайта и в форме создания объявления (`lib`-логики нет, всё в `/api/games/suggest` в `server.js` + `public/js/game-search.js`)
- Каталог с фильтрами: категория, цена от/до, сортировка (новые / цена / рейтинг продавца), поиск по названию товара и игре
- Карточка товара: описание, продавец с рейтингом и числом сделок, покупка одним кликом (создаёт реальный заказ, уменьшает остаток, увеличивает счётчик сделок продавца) — без ввода карты, это симуляция сделки внутри площадки
- Похожие товары той же категории
- Лента "Только что продано" под шапкой (демо-активность)
- Выставление товара на продажу — форма доступна вошедшему пользователю: игра выбирается через тот же поиск (RU/EN), объявление сразу появляется в общем каталоге и на странице игры; на самой странице игры есть кнопка «Продать», которая уже подставляет в форму игру (и раздел, если открыта вкладка категории)
- До 4 фото на объявление (JPG/PNG/WEBP, каждое до 5 МБ) — обложка на карточке и пролистывание стрелками/точками на странице товара; если фото не загружены, используется декоративная плашка с кольцами (см. дизайн)
- Для категории «Аккаунты» обязательны: количество предметов/скинов на аккаунте и 2-3 приметных названия (например, «Сирена», «Ferrari») — по ним же работает общий поиск по сайту
- Регистрация и вход: пароли хешируются (bcrypt), опция «Запомнить меня» — долгоживущая сессия вместо разовой на одну вкладку
- Личный кабинет: «Мои покупки», «Мои продажи», «Мои объявления», рейтинг, сумма потрачено/заработано
- Чат «Вопросы по товару» под карточкой, с двухуровневой модерацией:
  - **мгновенно, без ИИ** блокируются ссылки, прямые контакты (@username, t.me/), названия сторонних площадок и мессенджеров — в том числе написанные другими буквами, транслитом или вразрядку по буквам/слогам (сравнение по нормализованному "скелету" слова — `lib/messageFilter.js`)
  - **через ИИ-модерацию** (Claude API) проверяется неоднозначный случай "похоже на номер телефона, переданный по частям в нескольких сообщениях" — модель смотрит на контекст переписки, чтобы не путать реальный номер со случайными цифрами (цена, количество, уровень). Если ключ не настроен или запрос не удался — резервная эвристика (9+ цифр подряд при склейке последних сообщений). Логика — в `lib/aiModeration.js`
- Адаптивная вёрстка

### Настройка ИИ-модерации (необязательно)
1. Скопировать `.env.example` в `.env`
2. Вписать свой ключ с [console.anthropic.com](https://console.anthropic.com/) в `ANTHROPIC_API_KEY`
3. Без этого шага сайт работает как обычно — эта конкретная проверка идёт по резервным правилам

### Тестовые аккаунты (пароль везде `password123`)
- `demo` — покупатель с готовой историей покупок в профиле
- `shadowtrade`, `vega_market`, `progoods`, `nightseller`, `arenadeals` — продавцы; у каждого несколько вручную составленных объявлений (не рандомная генерация) — так каталог не пустой, но и не завален штампованными карточками. Основной способ пополнить каталог — реальная форма «Выставить товар»

## Запуск

```bash
npm install
cp .env.example .env   # заполнить при желании, можно оставить пустым
npm start
```

Открыть в браузере: http://localhost:3000

При первом запуске автоматически создастся `db/database.sqlite` и заполнится тестовыми данными (см. `db/init.js`). Пересоздать базу с нуля:

```bash
rm db/database.sqlite
npm run seed
```

## Безопасность
- Секреты — только через переменные окружения (`.env`, добавлен в `.gitignore`); `.env.example` содержит только плейсхолдеры
- Пароли хранятся хешированными через bcrypt, в открытом виде — никогда
- Все проверки владения (мой заказ / моё объявление) выполняются на сервере при обращении к базе
- Каждый изменяющий данные эндпоинт проверяет авторизацию (`requireAuth`) на сервере
- При создании/обновлении записей — явный список разрешённых полей, входящий объект целиком не сохраняется
- Валидация входных данных на сервере (длина, диапазоны, формат); `:id` в URL проверяется как положительное целое
- Все SQL-запросы параметризованы (`better-sqlite3` prepared statements), склейки строк нет; сортировка — через white-list допустимых значений
- Токены сессий и CSRF генерируются криптографически случайно (`crypto.randomBytes`, без `Math.random`)
- CSRF-защита (double-submit cookie) на всех изменяющих данные формах
- Rate limiting на вход, регистрацию и отправку сообщений в чате (`express-rate-limit`)
- Cookie сессии и CSRF — `httpOnly`, `secure` (в production), `SameSite=Lax`
- Секрет сессии — из `SESSION_SECRET`; в production без него сервер не запустится
- `helmet` (CSP и другие security-заголовки) + CORS закрыт по умолчанию (включается точечно через `ALLOWED_ORIGIN`)
- В production клиенту не показываются стек-трейсы ошибок — только в серверный лог
- Пароли и секреты не попадают в логи
- Загрузка фото (`multer`): проверка реального MIME-типа (не расширения из имени файла), лимит 5 МБ и 4 файла, имя файла на диске — случайное (`crypto.randomBytes`), исходное имя от пользователя никогда не используется как путь

## Структура проекта

```
├── server.js                    # роуты Express
├── db/
│   ├── init.js                  # схема таблиц + сид тестовыми данными (игры, категории, товары)
│   └── index.js                 # подключение к SQLite + lower_ru() для регистронезависимого поиска по кириллице
├── lib/
│   ├── messageFilter.js         # мгновенный фильтр чата (ссылки/контакты/площадки)
│   ├── aiModeration.js          # ИИ-модерация подозрения на номер по частям
│   └── sqliteSessionStore.js    # хранилище сессий на SQLite
├── views/                       # EJS-шаблоны (в т.ч. game.ejs — страница игры с вкладками)
│   └── partials/                # шапка, лента продаж, карточка, плейсхолдер-арт, подвал
└── public/
    ├── css/style.css            # вся визуальная тема
    ├── js/
    │   ├── game-search.js       # автодополнение поиска игр (шапка + форма объявления)
    │   ├── sell-form.js         # форма объявления: поля для "Аккаунтов" + превью фото
    │   └── gallery.js           # пролистывание фото на странице товара
    └── uploads/products/        # загруженные фото объявлений (не в git, см. .gitignore)

deploy/                          # конфиги для деплоя на VPS — см. DEPLOY.md
├── gearvault.service            # systemd-юнит (автозапуск + перезапуск при падении)
├── nginx.conf                   # обратный прокси Nginx -> Node
└── update.sh                    # обновление кода на сервере одной командой
```
